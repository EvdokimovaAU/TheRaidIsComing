# Контекстное меню строительства

Сценарий: `E → предпросмотр лучников → ЛКМ → меню → выбор → строительство → предпросмотр лучников`.
Повторное `E` выключает строительство, в том числе при открытом меню. ПКМ в меню
отменяет выбор; ПКМ вне меню сохраняет прежнее поведение отмены предпросмотра.
ЛКМ вне открытого меню только закрывает его. `1/2` отключены в C++; `3` и `Q`
сохраняют прежние действия. Преграда строится напрямую и завершает свой предпросмотр.

## Почему расширен компонент

1. `FreezePreview()` скрывает существующий Actor, останавливает его Tick и
   возвращает мировой центр основания предпросмотра на плоскости зоны, а не
   позицию pivot Actor. Подсветка зон сохраняется.
   Обычный `TryPlacePreview()` блокируется до завершения выбора.
2. `TryPlaceAt()` выбирает класс через прежний `StartPreview()` и вызывает прежний
   `TryPlacePreview()`. На время вызова источник позиции заменён сохранённой точкой,
   а не лучом от курсора над кнопкой. Высота рассчитывается по прежним данным меша
   выбранного класса, поэтому разные pivot/высоты башен не погружают их в землю.
   Различия pivot по XY также компенсируются: центр основания остаётся на месте.
   Прежний поиск допустимого положения используется повторно; результат, который
   сдвигает башню от сохранённой точки XY или меняет уровень зоны Z, отклоняется.
3. `OnPlacementRejected` передаёт причину из существующих веток отказа. Ранее они
   только писали UE_LOG; отдельного пользовательского механизма уведомлений в
   исходниках не найдено. Контроллер показывает сообщение средствами GEngine.

Алгоритмы геометрии зон, пересечений, преград, создания/инициализации зданий,
оплаты и навигации не переписаны. RICMoneyComponent не изменён. Контроллер и
виджет не создают здания и не проверяют баланс. Существующая повторная проверка
реального Actor после SpawnActor также сохранена: при таком отказе компонент
уничтожает временно созданный Actor без оплаты.

## Настройка Unreal Editor

1. Закройте Editor и соберите `RaidIsComingEditor / Win64 / Development` обычной
   сборкой (не только Live Coding), затем снова откройте проект UE 5.8.
2. Откройте `/Game/UI/WBP_BuildMenu`. В **Class Settings → Parent Class** проверьте
   родителя. Сейчас это `UserWidget`: выберите **File → Reparent Blueprint →
   RICBuildMenuWidget** (в списке без префикса U). Не создавайте другой виджет.
3. В Designer проверьте точные имена и **Is Variable** у всех четырёх элементов:
   `Button_ArcherTower`, `Button_MageTower` (Button), `Text_ArcherTower`,
   `Text_MageTower` (TextBlock). Они обязательны для BindWidget. Compile должен
   пройти без ошибок отсутствующих свойств или несовпадения типов.
4. На обеих кнопках выключите **Is Focusable**. Оставьте **Click Method = Down And Up**:
   кнопка требует собственного нажатия и отпускания. У Canvas/UserWidget задайте
   **Visibility = Not Hit-Testable (Self Only)**, у кнопок — **Visible**. У текстов
   допустимо **Not Hit-Testable (Self & All Children)**. Это настройки ввода;
   размеры, слоты, anchors, brushes, Normal/Hovered/Pressed и плашки не меняйте.
5. В Graph WBP отключите прежние OnClicked/OnPressed/OnReleased, которые создают
   башню, списывают деньги, закрывают меню либо вызывают строительство напрямую.
   C++ подписывает обе OnClicked автоматически. Удалите старые bindings Text и
   SetText в Construct/PreConstruct, которые выводят названия/фиксированные цены:
   значения двух TextBlock теперь заполняются только числовой ConstructionCost.
   Несвязанные декоративные анимации оставьте, если они не меняют ввод/цены.
6. Откройте `/Game/Blueprints/Buildings/BP_RICPlayerController`. В **Class Settings**
   родитель должен быть `RaidIsComingPlayerController` (по текущим данным уже так).
   В **Class Defaults** назначьте:

   | Поле | Значение |
   |---|---|
   | Construction → Archer Tower Class | BP_ArcherTower |
   | Construction → Mage Tower Class | BP_MageTower |
   | Construction → Barrier Class | BP_Barrier |
   | Construction → Menu → Build Menu Widget Class | WBP_BuildMenu |

   В ConstructionComponent сохраните существующий PreviewMaterial. В башнях
   оставьте корректные BuildingMesh, BuildingType и ConstructionCost. Цена меню
   читается при каждом открытии из тех же CDO, что использует оплата.
7. В Graph контроллера отключите старую реализацию меню и дублирующие события
   E, 1, 2, ЛКМ/IA_SetDestination, ПКМ, если они вызывают StartPreview,
   TryPlacePreview, CancelPreview, CreateWidget/RemoveFromParent для меню или
   списание золота. Не отключайте несвязанный BeginPlay/HUD/Defeat, управление
   камерой, Q и преградами. C++ сохраняет один путь ЛКМ: Enhanced Input, если
   назначены оба SetDestinationClickAction и DefaultMappingContext; иначе BindKey.
8. Проверьте **Project Settings → Maps & Modes → Default GameMode**, затем
   **World Settings → GameMode Override** текущей карты. Именно используемый
   GameMode должен иметь **Player Controller Class = BP_RICPlayerController**.
   В конфигурации проекта Default GameMode сейчас BP_TopDownGameMode; его поле и
   возможный override карты нужно проверить в Editor. Не меняйте Pawn и прочие
   поля GameMode для подключения меню.
9. Compile и Save изменённых Blueprint, затем Play в целевой карте. Во время Play
   проверьте в World Outliner реальный PlayerController, а не только Class Defaults.

## Проверка в Play

1. Нажать E: зоны подсвечены, лучники следуют за мышью без 1. Проверить 1/2 —
   они не переключают тип. Навести на доступную зону, нажать ЛКМ: башни ещё нет,
   меню над точкой, предпросмотр скрыт, зоны остались.
2. Отвести мышь к каждому сектору. Проверить Hovered/Pressed, затем построить
   лучников и магов отдельными попытками. Место не следует за кнопкой, за одну
   попытку появляется одна башня и снимается одна стоимость. Сразу доступен
   следующий предпросмотр лучников без E.
3. Открыть меню, нажать ПКМ над кнопкой и за пределами меню. Затем повторить
   с ЛКМ вне меню. Нет здания/оплаты, меню закрыто, лучники восстановлены.
4. Проверить E при открытом меню и при обычном предпросмотре: меню и предпросмотр
   исчезают, зоны выключены. Следующий E снова выбирает лучников.
5. Проверить нехватку золота, занятую позицию, слишком большую башню у края
   зоны и изменение доступности зоны между открытием и выбором. Нет оплаты/
   оставшегося здания, появляется причина, меню закрывается, режим продолжается.
6. Изменить ConstructionCost в Class Defaults BP_ArcherTower/BP_MageTower,
   Compile, снова открыть меню: только новое число, без имени и слова gold.
7. Проверить удержание ЛКМ, быстрые повторные клики, выход по E во время меню,
   края окна и разные разрешения/DPI. Меню позиционируется один раз, без Tick;
   учитываются границы секторов Canvas, включая пустые отступы Designer.
8. Проверить 3 и преграды, Q и волны, обычное движение после выхода из строительства.

## Автоматическая проверка

В **Tools → Test Automation** (или Session Frontend → Automation) найдите
`RaidIsComing.Construction.BuildMenu.SavedPosition` и запустите. Тест использует существующие Blueprint башен и
временную пустую карту, поэтому сначала сохраните свою рабочую карту.

Он проверяет фиксацию/скрытие предпросмотра, сохранение точки при Tick, ровно одно
создание/списание, повторный вызов, пересечения, недостаток золота, изменение
доступности/размера зоны и отмену. Временные настройки CDO восстанавливаются.
Проверяется также переход от предпросмотра лучников к созданию магов с ценой BP_MageTower.
Тест не заменяет проверку UMG мышью в Play и не изменяет ассеты проекта.

## Ограничения

- Для работы в Play нужно выполнить Reparent и назначение класса меню выше;
  эти изменения бинарных ассетов намеренно оставлены настройками Editor.
- Полная визуальная проверка UMG и событий мыши выполняется после этих настроек.
- Меню сохраняет размеры дизайна. Если само содержимое больше viewport, показать
  его целиком без масштабирования невозможно; текущий код прижимает его к краю.
- Уведомление использует AddOnScreenDebugMessage и подходит для Development/Editor.
  Для Shipping подключите OnPlacementRejected к игровому HUD: debug-сообщения
  там не гарантированы. Готового HUD уведомлений в доступном C++ не обнаружено.
- Проверки маршрутов и особенности инициализации Blueprint остаются ровно теми,
  которые уже предоставляет компонент; новые правила навигации не добавлены.
